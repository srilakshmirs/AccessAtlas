# AccessAtlas

**Cross-platform identity risk detection** — links AD, AWS IAM and Okta
accounts to a single HR identity, computes effective privilege across nested
groups and federation, and detects risky patterns with evidence and remediation
advice.

> Synthetic dataset; all identities are fictional. Never auto-revokes access.

---

## Quick start

### 1. Clone and install

```bash
git clone https://github.com/<your-org>/AccessAtlas.git
cd AccessAtlas

# Create a virtual environment (Python 3.11 required)
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

pip install -e ".[dev]"
```

### 2. Place the dataset files

Copy the three XLSX files into `data/raw/` (they are gitignored):

```
data/raw/
  AccessAtlas_Dataset_Core.xlsx
  AccessAtlas_Dataset_Events_Part1.xlsx
  AccessAtlas_Dataset_Events_Part2.xlsx
```

### 3. Convert data (one-time)

```bash
# Convert XLSX → Parquet and generate CI fixture files
python scripts/convert_data.py --fixture
```

Output goes to `data/processed/` (gitignored) and `tests/fixtures/` (committed).

> **Note:** Converting the events files reads ~32 MB of XLSX via openpyxl.
> Measured on Intel Core 7 150U / 15 GB RAM: median **80 s** for the XLSX read.
> The resulting Parquet file loads in **0.070 s** (warm read) at runtime.

### 4. Run tests

```bash
pytest tests/ -v
```

Tests use `tests/fixtures/` so they work without the full dataset.

### 5. Identity Resolution & Evaluation (M2)

```bash
# Calibrate fuzzy matching threshold on train split and evaluate test/holdout:
python scripts/tune_thresholds.py
```

### 6. Privilege Graph & Entitlement Evaluation (M3)

```bash
# Construct privilege graph, compute direct/effective tiers and evaluate splits:
python scripts/evaluate_privilege.py
```

### 7. Run the API (M4)

Start the local API development server with Uvicorn:

```bash
uvicorn accessatlas.api.main:app --reload
```

Example requests:

```bash
# System health and findings count:
curl http://localhost:8000/health

# List identities (paginated, with optional tier / kind filters):
curl "http://localhost:8000/identities?page=1&size=20&max_tier=1"

# Inspect a single identity with platform accounts, grant paths, and findings:
curl http://localhost:8000/identities/E100086

# List explainable security findings (filtered by rule, platform, severity):
curl "http://localhost:8000/findings?severity=high&rule=offboarding_gap"

# Retrieve full evidence and remediation advice for a single finding:
curl http://localhost:8000/findings/FND-offboarding_gap-E100086

# Retrieve scenario-level evaluation metrics:
curl "http://localhost:8000/evaluation?split=train"
```

## Project structure

```
accessatlas/        Python package (ingestion, resolution, evaluation, graph, rules, api)
tests/              pytest tests (uses tests/fixtures/ for fast CI)
scripts/            Utility scripts (convert_data.py, tune_thresholds.py, evaluate_privilege.py)
docs/               Architecture, data dictionary, tech stack, ADRs, milestone notes
data/raw/           Source XLSX files (gitignored)
data/processed/     Parquet files generated by convert_data.py (gitignored)
tests/fixtures/     Small fixture sample committed to git for CI
frontend/           React + Vite app (added in M4)
Dockerfile          Backend container
docker-compose.yml  Runs backend (and frontend in M4)
.github/workflows/  GitHub Actions CI
```

## Key rules

- **GT_ sheets are evaluation-only.** No detection or resolution code may read
  them. CI enforces this automatically (`tests/test_gt_isolation.py`).
- **Never commit data files.** `data/` is gitignored; only `tests/fixtures/` is committed.
- **Never auto-revoke access.** The system recommends remediation; humans act.
